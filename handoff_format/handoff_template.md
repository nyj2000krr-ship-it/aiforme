# 단계 간 산출물 전달 표준 양식

이 양식은 각 에이전트가 작업을 마치고 다음 단계 에이전트로 결과물을 넘길 때 사용하는 표준입니다.

---

## 사용법

각 에이전트의 시스템 프롬프트 마지막에는 `[다음 단계 전달 형식]` 항목이 있습니다. 작업이 끝나면 에이전트는 아래 양식대로 산출물을 출력합니다.

다라미님은 출력된 마크다운을 `===이전 단계 산출물 시작===` 부터 `===여기까지...===` 까지 통째로 복사해서, 다음 단계 Gem/Project의 첫 메시지로 붙여넣으면 됩니다.

---

## 📋 양식: 설계 → 개발

```markdown
===이전 단계 산출물 시작===

# 설계서 v1

{모바일 / 웹 / 반응형 중 선택, 이유 포함}

### [홈]
- 로고
- 메인 CTA 버튼
- ...

### [에디터]
- ...

## 3. 사용자 시나리오 (3~5개)
### 시나리오 1: {제목}
- Step 1: {...}
- Step 2: {...}

## 4. 데이터 설계 (테이블 명세)
### 테이블: users
| 컬럼명 | 타입 | 제약조건 | 설명 |
|--------|------|---------|------|
| id | UUID | PK | 사용자 식별자 |
| ... | ... | ... | ... |

### 관계
- users (1) ─── (N) contents

## 5. API 설계
### POST /api/contents
- 요청: { ... }
- 응답: { ... }

## 6. 다음 단계로 결정 필요한 사항
- {...}

===여기까지 복사해서 다음 Gem/Project에 붙여넣기===
```

## 📋 작성 시 공통 규칙

1. **빈 칸은 두지 않기.** 결정되지 않았다면 "결정 보류"라고 명시.
2. **출처 라벨 유지.** 이전 단계의 출처/신뢰도 라벨은 다음 단계에서도 보존.
3. **버전 표기.** v1, v2 식으로 산출물 버전을 명시. 수정 시 v1.1, v1.2.
4. **다음 단계로 미해결 항목 명시.** 그래야 다음 에이전트가 모호함 없이 작업 시작.
5. **표 형식 유지.** 마크다운 표를 깨뜨리지 않기 (Claude/Gemini 양쪽에서 잘 렌더링됨).

---

## 📋 양식 추가 예정

- 개발 → 소스관리
- 소스관리 → 배포
- 배포 → 출시
- 출시 → 유지보수
- 유지보수 → 기획 (피드백 루프)
