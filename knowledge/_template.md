# 지식 파일 작성 템플릿

이 폴더(`knowledge/`)에는 에이전트가 참고할 도메인 지식과 트렌드 자료를 저장합니다. 각 자료는 아래 표준 양식으로 작성합니다.

---

## 📄 표준 헤더 양식

모든 지식 파일은 다음 헤더로 시작합니다:

```markdown
# [자료 제목]

> **카테고리:** 시장 트렌드 / 경쟁사 분석 / 도메인 지식 / 사용자 리서치 (택1)
> **작성일:** YYYY-MM-DD
> **갱신 주기:** 주 1회 / 월 1회 / 분기 1회 / 연 1회
> **데이터 기준일:** YYYY-MM-DD (자료 안의 통계가 언제 시점인지)
> **신뢰도:** 높음 / 중간 / 낮음
> **다음 갱신 예정일:** YYYY-MM-DD

---
```

---

## 📋 파일명 규칙

```
[카테고리]_[주제]_[YYYY-MM-DD].md
```

**예시:**
- `market_trends_content_automation_2026-04-26.md`
- `competitor_analysis_jasper_copy_ai_2026-04-26.md`
- `domain_knowledge_english_education_market_2026-04-26.md`
- `user_research_youtube_creator_pain_points_2026-04-26.md`

**규칙:**
- 모두 소문자 + 언더스코어
- 날짜는 항상 파일명 끝에
- 같은 주제 갱신 시 새 날짜로 새 파일 생성 (구버전은 `_archive/` 폴더로)

## ⚙️ 양식 준수 이유

이 양식을 일관되게 지키면:

1. **에이전트가 자료를 잘 인용함.** 에이전트는 구조화된 자료에서 정확한 인용을 더 잘함.
2. **다라미님이 자료를 빠르게 검색함.** 모든 파일이 같은 구조라 어디에 무엇이 있는지 예측 가능.
3. **신뢰도 추적이 쉬움.** 헤더만 봐도 자료의 신선도와 출처를 한눈에 파악.
4. **갱신 누락이 줄어듦.** "다음 갱신 예정일"이 명시되어 있어 갱신 알람을 만들기 쉬움.

---

## 🗄️ 구버전 자료 처리

같은 주제의 자료를 갱신할 때는:

1. 신규 파일을 새 날짜로 만들기 (예: `market_trends_content_automation_2026-05-26.md`)
2. 기존 파일을 `knowledge/_archive/` 폴더로 이동
3. 각 플랫폼(Claude/Gemini) Knowledge에서도 구버전 삭제 + 신버전 업로드
4. `CHANGELOG.md`에 갱신 내역 기록
